## UPGRADING

To upgrade from 3.x to 4.x you will not be able to keep the virtual file system
or slave files. Userfiles will be converted correctly if password is not encrypted.

Follow the installation documentation and do now install into the version 4.x:

https://github.com/drftpd-ng/drftpd/blob/master/README.md

Next if you have user files that predate 4.x, they need to be converted. There is a script in "TODO"
that is called "TODO: Migrate-v3-to-v4.sh". Next start the master and readd slaves.
Themes and all .conf files have to be rebuild in 4.x. Copying over the files will
give you alot of problems. The virtual file system will be built when slaves are
merged for the first time.

## To upgrade from 4.x to the latest:

Before performing a upgrade of DrFTPD, make sure to delete the following folders:
- src

### Compile
- Run mvn clean
- Run mvn validate
- Run mvn install

Regarding the configuration files, check that you are using the new ones once the build is done.

### Command configuration files (4.0.12 and later)

Command definitions in config/commands/ftp and config/commands/irc now ship as X.conf.dist.
DrFTPD loads X.conf when it exists and falls back to X.conf.dist otherwise.

- If you kept the X.conf files from an earlier version, they now completely replace the new
  X.conf.dist files. Commands added in later releases will not show up until you merge the new
  X.conf.dist into your X.conf by hand, or delete your X.conf to use the shipped defaults.
- If a command moved from one file to another between versions (for example the request commands
  moving out of core.conf), an old customised core.conf together with the new request.conf.dist
  defines the command twice, and the master stops at startup with "already mapped". Remove the
  duplicate definition from your own X.conf to fix it.
- If you never customised a command file, delete your X.conf so the shipped X.conf.dist is used.

### Log4j 2 master configuration (after 4.0.12)

If you use your own copy of config/log4j2-master.xml (the build copies it to runtime/master/config
and may not overwrite an edited one), merge these changes into it:

- The commands, vfs and events appenders now archive to commands-, vfs- and events-<date>.log.gz
  instead of index-<date>.log.gz, so archives are no longer overwritten and the 90 day cleanup works.
- The logger names for imdb, tvmaze and indexmanager now use the real package names
  (org.drftpd.imdb.master, org.drftpd.tvmaze.master, org.drftpd.master.commands.indexmanager),
  and the unused org.drftpd.master.network.BaseFtpConnection.service logger is removed.
- The org.drftpd.master.commands.usermanagement logger is now at level info, so user and group
  changes are written to sysop.log.
